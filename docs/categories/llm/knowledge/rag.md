# RAG 检索增强生成 (Retrieval-Augmented Generation)

## 1. 核心思想

将检索系统与生成模型结合，让模型在生成时可以参考外部知识库。

$$
P(y|x) = \sum_{z \in \text{Ret}(x)} P(y|x, z) P(z|x)
$$

其中：
- $x$：查询
- $z$：检索到的文档
- $y$：生成的回答

---

## 2. 架构设计

### 2.1 组件

```
查询 → [检索器] → 相关文档 → [生成器] → 回答
         ↑                    ↑
      向量数据库            大语言模型
```

| 组件 | 作用 | 代表技术 |
|------|------|----------|
| 检索器 | 找到相关文档 | BM25、DPR、Contriever |
| 向量数据库 | 存储文档嵌入 | FAISS、Milvus、Pinecone |
| 生成器 | 基于文档生成 | GPT-4、LLaMA、Qwen |

### 2.2 流程

1. **文档预处理：** 分块 → 嵌入 → 存入向量数据库
2. **查询处理：** 查询 → 嵌入 → 检索 Top-K 文档
3. **生成：** 查询 + 文档 → LLM → 回答

---

## 3. 检索器

### 3.1 稀疏检索 (BM25)

**原理：** 基于词频和逆文档频率

$$
\text{BM25}(D, Q) = \sum_{i=1}^{n} \text{IDF}(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot |D|/avgdl)}
$$

**优点：** 精确匹配，可解释
**缺点：** 无法理解语义

### 3.2 稠密检索 (DPR)

**原理：** 用双编码器将查询和文档映射到同一向量空间

$$
\text{Score}(Q, D) = \text{Encoder}_Q(Q)^T \cdot \text{Encoder}_D(D)
$$

**训练：** 对比学习，拉近相关对，推远不相关对

### 3.3 混合检索

结合 BM25 和 DPR：

$$
\text{Score}_{hybrid} = \alpha \cdot \text{BM25} + (1-\alpha) \cdot \text{DPR}
$$

**推荐：** $\alpha = 0.5$

## 4. 向量数据库

### 4.1 核心功能

| 功能 | 说明 |
|------|------|
| 向量存储 | 高维向量持久化 |
| 相似度搜索 | ANN 近似最近邻 |
| 过滤 | 元数据过滤 |
| 更新 | 增量更新 |

### 4.2 ANN 算法

| 算法 | 速度 | 精度 | 内存 |
|------|------|------|------|
| 暴力搜索 | 慢 | 100% | 高 |
| IVF | 中 | 95% | 中 |
| HNSW | 快 | 98% | 高 |
| PQ | 快 | 90% | 低 |

### 4.3 选择指南

| 场景 | 推荐 | 原因 |
|------|------|------|
| 小规模 (<1M) | FAISS-Flat | 简单高效 |
| 大规模 (>100M) | FAISS-IVF+PQ | 内存效率 |
| 低延迟 | HNSW | 查询速度快 |
| 云部署 | Pinecone/Milvus | 托管服务 |

## 6. 高级技术

### 6.1 查询改写

**问题：** 用户查询可能不够清晰。

**解决：** 用 LLM 改写查询

```python
rewritten_query = llm.generate(f"改写以下查询使其更清晰：{query}")
docs = retrieve(rewritten_query)
```

### 6.2 多跳检索

**问题：** 单个文档无法回答复杂问题。

**解决：** 迭代检索

```
查询 → 检索 → 中间回答 → 新查询 → 检索 → 最终回答
```

### 6.3 Reranker

**问题：** 检索器可能不够精确。

**解决：** 用交叉编码器重排序

$$
\text{Score}(Q, D) = \text{CrossEncoder}(Q, D)
$$

**流程：** 粗排（DPR）→ 精排（CrossEncoder）→ 生成

## 7. 评估指标

### 7.1 检索质量

| 指标 | 说明 |
|------|------|
| Recall@K | Top-K 中相关文档的比例 |
| MRR | 第一个相关文档的排名倒数 |
| NDCG | 考虑排名位置的增益 |

### 7.2 生成质量

| 指标 | 说明 |
|------|------|
| 事实准确性 | 回答是否与文档一致 |
| 引用率 | 标注引用的比例 |
| 幻觉率 | 无中生有的比例 |
| 人类评分 | 整体质量 |

## 8. 实践指南

### 8.1 文档分块

| 策略 | 块大小 | 适用场景 |
|------|--------|----------|
| 固定长度 | 512 token | 通用 |
| 按段落 | 可变 | 结构化文档 |
| 按语义 | 可变 | 长文档 |

**重叠：** 相邻块重叠 10-20%，避免信息丢失。

### 8.2 嵌入模型选择

| 模型 | 维度 | 多语言 | 速度 |
|------|------|--------|------|
| text-embedding-ada-002 | 1536 | 一般 | 快 |
| BGE-large-zh | 1024 | 中文优 | 中 |
| E5-large | 1024 | 多语言 | 中 |
| GTE-large | 1024 | 多语言 | 快 |

### 8.3 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 检索不相关 | 查询模糊 | 查询改写 |
| 生成幻觉 | 文档不充分 | 增加检索数量 |
| 延迟高 | 检索慢 | 用 HNSW 索引 |
| 成本高 | LLM 调用多 | 缓存热门查询 |

## 9. 数学推导

### 9.1 DPR 训练损失

**对比学习损失：**

$$
\mathcal{L} = -\log \frac{\exp(\text{sim}(q_i, d_i^+))}{\exp(\text{sim}(q_i, d_i^+)) + \sum_{j=1}^{k} \exp(\text{sim}(q_i, d_i^-))}
$$

其中 $d_i^+$ 是正样本，$d_i^-$ 是负样本。

### 9.2 生成概率

$$
P(y|x) = \sum_{z} P(y|x, z) P(z|x)
$$

实践中只取 Top-K：

$$
P(y|x) \approx \sum_{z \in \text{TopK}} P(y|x, z) P(z|x)
$$
