# 思维链 (Chain-of-Thought, CoT)

## 1. 核心思想

通过在提示中展示中间推理步骤，让大模型学会"一步一步思考"，大幅提升复杂推理任务的表现。

---

## 2. 原始论文 (Wei et al., 2022)

### 2.1 动机

标准提示 (Standard Prompting)：
```
Q: 小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个？
A: 6 个
```

思维链提示 (CoT Prompting)：
```
Q: 小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个？
A: 小明开始有 5 个苹果。吃了 2 个后剩下 5-2=3 个。又买了 3 个，所以 3+3=6 个。答案是 6 个。
```

### 2.2 关键发现

**发现 1：规模依赖**

只有足够大的模型（约 100B+）才能从 CoT 中受益。

| 模型规模 | 标准提示 | CoT 提示 |
|----------|----------|----------|
| 10B | 17.7% | 17.9% |
| 100B | 17.7% | 40.7% |
| 540B | 17.7% | 58.1% |

**发现 2：任务依赖**

CoT 对需要多步推理的任务效果最显著：
- 数学应用题 (GSM8K)：+40%
- 常识推理 (CommonsenseQA)：+15%
- 符号推理：+30%

## 3. 变体

### 3.1 Zero-Shot CoT

**思想：** 不需要示例，只需添加"Let's think step by step"。

```
Q: 小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个？
Let's think step by step.
```

**效果：** 比标准提示好，但不如 Few-Shot CoT。

### 3.2 Self-Consistency

**思想：** 采样多条推理路径，取最一致的答案。

```
for i in 1...N:
    path_i = sample_cot_response(query)
    answer_i = extract_answer(path_i)
final_answer = majority_vote(answers)
```

**效果：** 显著提升准确率（+5-15%）。

### 3.3 Tree-of-Thought (ToT)

**思想：** 探索多棵推理树，用搜索算法（BFS/DFS）找到最优路径。

```
初始化：根节点 = 问题
for step in 1...T:
    for node in current_level:
        children = generate_thoughts(node)
        scores = evaluate(children)
    next_level = select_top_k(children, scores)
```

**适用：** 需要规划的任务（如 24 点游戏、写作）。

### 3.4 Auto-CoT

**思想：** 自动构建 CoT 示例，无需人工标注。

```
1. 聚类问题
2. 从每类选代表问题
3. 用 Zero-Shot CoT 生成推理
4. 作为 Few-Shot 示例
```

## 4. 数学推导

### 4.1 推理路径概率

设推理路径 $r = (r_1, r_2, ..., r_k)$，答案 $a$。

**标准提示：**
$$
P(a|x) = \sum_r P(a|r, x) P(r|x)
$$

**CoT 提示：**
$$
P_{CoT}(a|x) = P(a|r^*, x) \quad \text{where } r^* = \text{demonstration}
$$

### 4.2 Self-Consistency

$$
P_{SC}(a|x) = \sum_{r: \text{extract}(r)=a} P(r|x)
$$

选择概率最高的答案：
$$
a^* = \arg\max_a P_{SC}(a|x)
$$

## 5. 实践指南

### 5.1 示例设计

**好示例的特征：**

| 特征 | 说明 |
|------|------|
| 清晰 | 每步都有明确目的 |
| 完整 | 展示完整推理过程 |
| 多样 | 覆盖不同推理类型 |
| 简洁 | 避免冗余信息 |

**示例模板：**

```
Q: [问题]
A: [第一步推理]。[第二步推理]。... 答案是 [答案]。
```

### 5.2 提示模板

```
以下是几个推理示例：

Q: {example_1_question}
A: {example_1_reasoning}

Q: {example_2_question}
A: {example_2_reasoning}

Q: {target_question}
A:
```

### 5.3 参数选择

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 示例数 | 3-8 | 太少效果差，太多浪费 |
| 采样数 (SC) | 5-40 | 越多越好，但收益递减 |
| 温度 | 0.7 | 平衡多样性与质量 |

## 6. 应用场景

### 6.1 数学推理

**GSM8K 示例：**

```
Q: 一个商店有 120 个苹果。第一天卖了 30 个，第二天卖了剩下的 1/3。还剩多少？
A: 开始有 120 个。第一天卖了 30 个，剩下 120-30=90 个。第二天卖了 90 的 1/3，即 30 个。所以剩下 90-30=60 个。答案是 60 个。
```

### 6.2 常识推理

```
Q: 把大象放进冰箱需要几步？
A: 第一步，打开冰箱门。第二步，把大象放进去。第三步，关上冰箱门。答案是 3 步。
```

### 6.3 符号推理

```
Q: 如果所有 A 都是 B，所有 B 都是 C，那么所有 A 都是 C 吗？
A: 所有 A 都是 B，意味着 A 是 B 的子集。所有 B 都是 C，意味着 B 是 C 的子集。根据传递性，A 是 C 的子集，即所有 A 都是 C。答案是是的。
```

## 7. 局限性

### 7.1 问题

| 问题 | 说明 |
|------|------|
| 规模依赖 | 小模型无法受益 |
| 错误传播 | 一步错，步步错 |
| 计算成本 | 生成更长序列 |
| 幻觉 | 推理过程可能不合理 |

### 7.2 解决方案

| 方法 | 说明 |
|------|------|
| Self-Consistency | 多路径投票 |
| 验证器 | 用另一个模型验证推理 |
| 分步验证 | 每步都检查 |
