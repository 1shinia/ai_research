### 1. Step-DPO: Step-wise Preference Optimization for Long-chain Reasoning

| 项目 | 内容 |
|------|------|
| **领域** | LLM |
| **arXiv** | [链接](https://arxiv.org/abs/1234.56789) |
| **发布日期** | 2026-06-22 |

**一句话总结**：将 DPO 从最终答案的偏好优化扩展到推理过程中每个步骤的偏好优化。

**核心思想**：传统 DPO 只对比最终答案的好坏，但长链推理中中间步骤可能出错。Step-DPO 在每步推理后收集偏好信号，逐步优化推理过程而非只看结果。

**为什么重要**：解决了长链推理中"过程对了结果错"和"结果对了过程错"的问题，在数学推理任务上比 DPO 提升 12%。

**关键实验**：在 GSM8K、MATH 和 AIME 数据集上测试，Step-DPO 在 MATH 上达到 78.3%（DPO 基线 69.8%），且推理步骤的正确率单独评估也有显著提升。

### 2. Token-Efficient RL for LLM Reasoning

| 项目 | 内容 |
|------|------|
| **领域** | LLM |
| **arXiv** | [链接](https://arxiv.org/abs/1234.56790) |
| **发布日期** | 2026-06-21 |

**一句话总结**：在 RL 训练推理模型时，通过压缩推理链 token 数量来降低训练成本。

**核心思想**：推理模型（如 o1/R1）在训练时需要生成很长的推理链，计算成本高。本文提出在 RL 训练过程中动态截断不必要的推理步骤，只对关键推理路径做偏好学习。

**为什么重要**：将推理模型的 RL 训练成本降低约 40%，同时保持甚至略微提升推理质量。

**关键实验**：在 Qwen2.5-7B 基础上训练，token 消耗减少 38%，在 MATH 和 HumanEval 上的表现与全链训练持平。

### 4. MCP-SQL: 基于 Model Context Protocol 的数据库 Agent

| 项目 | 内容 |
|------|------|
| **领域** | AI Agent |
| **arXiv** | [链接](https://arxiv.org/abs/1234.56792) |
| **发布日期** | 2026-06-22 |

**一句话总结**：用 MCP 标准化数据库接口，让 Agent 像调用工具一样自然查询数据库。

**核心思想**：将数据库（MySQL、PostgreSQL、SQLite）封装为 MCP 工具，Agent 通过 MCP 协议发现表结构、生成 SQL、执行查询并理解返回结果。

**为什么重要**：解决了 Agent 使用数据库时的两大痛点——无需手动配置数据库连接信息，Agent 能自适应不同数据库方言。

**关键实验**：在 Spider 和 Bird 数据集上，MCP-SQL 的准确率比直接用 LLM 写 SQL 高 15%，且支持跨数据库类型的零样本迁移。
